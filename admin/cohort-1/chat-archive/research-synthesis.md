# AWAC 1기 대화 리서치 종합

## 결론

AWAC 1기의 가장 강한 가치는 “최신 AI 도구를 많이 알려주는 과정”이 아니라, **내 업무에서 무엇을 Agent로 만들지 판단하고, 비용과 품질을 통제하면서 실제 결과까지 내게 하는 과정**이었습니다.

참여자의 질문은 도구 이름보다 네 가지 결정에 집중됐습니다.

1. 지금은 대화형 AI로 충분한가, Agent를 만들어야 하는가?
2. 어떤 모델과 요금제를 써야 시간·토큰을 낭비하지 않는가?
3. 업무를 여러 Agent에게 어떻게 나누고 어디에서 검수해야 하는가?
4. 결과를 사람이 이해하고 신뢰할 수 있게 어떻게 다듬는가?

따라서 2기 운영과 도서 판매 모두 `도구 소개`보다 `판단 기준 + 실행 템플릿 + 실제 사례`를 앞세우는 편이 적합합니다.

## 조사 범위와 방법

- 자료: `[AWAC] 오프라인 스터디 1기` 카카오톡
- 기간: 2026-09-03 ~ 2026-10-10
- 범위: 대화 목록 338개 항목, 중복을 포함한 시스템 메시지·공지·대화 전부
- 처리: 265개 고유 텍스트 조각을 추출한 뒤 질문, 답변, 반응, 운영 이슈, 학습 성과로 코딩
- 미디어: 30개 중 19개 원본 복구, 11개는 카카오톡 보관기간 만료로 복구 불가
- 개인정보: 이름·이메일·개인 링크·얼굴 사진은 공개 분석에서 제거

이 자료는 채팅 참여자의 자발적 대화에 기반한 질적 연구입니다. 전체 참여자의 의견을 대표하는 설문 결과로 해석하면 안 됩니다.

## 테마별 발견

### 1. 학습보다 먼저 해결해야 한 것은 접근권한이었다

첫날 전후로 최소 8명이 노션 초대·계정·편집권한 문제를 겪었습니다. 문제는 개인의 디지털 역량이 아니라 `신청 이메일 ≠ 실제 가입 이메일`, 보기와 편집 권한의 차이, 초대 상태를 확인하는 절차 부재였습니다.

**인사이트:** 교육 경험의 첫 번째 제품은 강의가 아니라 환경 세팅입니다. 첫 30분의 마찰은 이후 과정의 자신감까지 떨어뜨릴 수 있습니다.

**개선:** 수업 전날 `로그인 → 페이지 열기 → 한 줄 작성 → 댓글 남기기`를 완료하면 체크되는 프리플라이트를 운영합니다.

### 2. 참가자는 “할 수 있나”보다 “언제 해야 하나”가 궁금했다

“이것도 AI로 자동화할 수 있나요?”라는 질문은 많았지만, 더 중요한 질문은 일회성 포트폴리오 작업을 Agent로 만들 필요가 있는지였습니다. 운영진이 제시한 `5회 이상 반복될 때 Agent 검토` 기준은 복잡한 기술 선택을 사업 판단으로 바꿨습니다.

**인사이트:** 초보자에게 필요한 것은 더 많은 사례 목록이 아니라 자동화하지 않을 기준입니다.

**기회:** `Agent를 만들지 말아야 할 때`를 전면에 내세운 콘텐츠는 흔한 “무엇이든 자동화” 메시지와 차별화됩니다.

### 3. 멀티 Agent의 진짜 장벽은 설계보다 비용·실패 대응이었다

낮은 요금제 가능 여부, 15분 넘는 실행, 모델을 낮추면 품질이 떨어지는지, 사용량과 리셋, 로컬 LLM 하드웨어가 연속 질문으로 나타났습니다.

**인사이트:** 멀티 Agent 학습에는 구조도와 함께 운영비·중단 기준·재시도 정책이 있어야 합니다.

**재사용 가능한 언어:** `모델 = 과제 난이도`, `effort = 생각 시간`, `고성능 모델 = 뇌`, `저비용·로컬 모델 = 손`.

### 4. 커리어 문제와 연결될 때 참여가 구체화됐다

경력기술서를 포트폴리오로 바꾸는 방법, 일반 직무의 디자인 레퍼런스, 이직에 적용하겠다는 후기가 나타났습니다. 기술 자체보다 자기 경력·업무 결과물에 연결됐을 때 후속 질문과 감사 반응이 이어졌습니다.

**인사이트:** 범용 AI 책·강의보다 `직무 결과물`을 입구로 쓰는 편이 전환에 유리합니다.

### 5. 문제 정의가 Agent 제작의 선행 제품이었다

참여자는 과제를 “잘 정리해서” 내려고 했고, 운영진은 오히려 친구에게 말하듯 현재 문제를 쓰라고 안내했습니다. HMW와 PRD는 도구 사용 전에 문제를 구조화하는 공통 프레임으로 기능했습니다.

**인사이트:** AWAC의 차별점은 Agent 빌더가 아니라 문제정의 코칭입니다. 이것은 도서의 핵심 메시지인 “도구 도입을 실제 성과로 바꾸는 판단 기준”과 일치합니다.

### 6. 설치·실행이 바로 되는 자료가 반응을 만들었다

리서치 Skill 공유 뒤 “파일 첨부 후 설치해줘” 같은 한 줄 사용법이 붙었고, GitHub 링크도 “복사해서 실행해줘”라는 행동으로 번역됐습니다.

**인사이트:** 콘텐츠의 단위는 설명글보다 `복사 가능한 한 문장 + 기대 결과 + 실패 시 대안`이어야 합니다.

### 7. 과정의 끝은 Alumni와 사례 생산의 시작이었다

마지막에는 실제 업무 활용, 이직 적용, 멀티 Agent 제작 후기가 나타났고 Alumni 방, 자료 공유, 무료 특강, LinkedIn 후기 동선이 제시됐습니다.

**인사이트:** 수료 커뮤니티는 단순 유지 채널이 아니라 다음 기수·도서·B2B 교육을 연결하는 증거 생산 시스템이 될 수 있습니다. 단, 후기와 사례의 외부 사용은 반드시 별도 동의를 받아야 합니다.

## 운영 우선순위

### P0 — 다음 기수 전에 반드시 반영

1. 노션·AI 도구·결제·브라우저를 확인하는 프리플라이트
2. 사진 4컷으로 된 입장 동선과 QR 활성화 시각 안내
3. 과제별 최저 모델, 예상 소요시간, 중단 기준
4. `대화형 AI → 단일 Agent → 멀티 Agent` 진입 기준
5. 공개 후기·사진·사례의 동의 여부를 별도 수집

### P1 — 교육 품질과 상품화를 동시에 높임

1. 문제정의, Agent 역할, 비용 라우팅, 품질검수 4종 워크시트
2. 직무별 완성 사례: HR, PM, 마케팅, 커리어 문서
3. 수료 후 30일 사용 회고와 실제 업무 성과 수집
4. Alumni 월 1회 오피스아워와 사례 발표

### P2 — 규모화 전 검증

1. 질문을 자동 분류하는 운영 Agent
2. 모델·요금제 변화에 맞춰 업데이트되는 비용 가이드
3. 기업용 `책 + 강연 + 워크시트 + 4주 실습` 패키지

## 한계와 추가 검증

- 반응이 없는 참여자의 의견은 채팅에 나타나지 않습니다.
- 질문 수는 중요도의 대략적인 신호이지 전체 수요 비율이 아닙니다.
- 4주 과정의 실제 업무성과·시간절감·비용절감은 채팅만으로 확인할 수 없습니다.
- 다음 기수에서는 시작/종료 설문에 `작업시간`, `재사용 횟수`, `월 AI 비용`, `실제 적용 여부`를 같은 문항으로 측정해야 합니다.
- 도서 판매 메시지는 먼저 작은 콘텐츠 실험으로 클릭·다운로드·구매를 확인한 뒤 확대해야 합니다.

# AWAC 1기 질문·답변 아카이브

## 정리 기준

2026년 9월 3일부터 10월 10일까지 카카오톡 대화 목록 338개 항목을 읽고, 참여자의 실제 질문과 운영진 답변을 주제별로 재구성했습니다. 실명, 이메일, 초대 링크, 개인 식별 정보는 제거했습니다. 아래 답변은 당시 대화의 맥락을 보존한 요약이며 일반적인 제품 보증이나 최신 기술 사양이 아닙니다.

## 핵심 질문과 답변

### 1. 노션 페이지는 열리는데 왜 작성할 수 없나요?

- 관찰: 최소 8명이 초대 누락, 잘못 제출한 계정, 보기 권한만 있는 상태를 보고했습니다.
- 당시 답변: 가입에 실제로 사용한 이메일을 다시 확인해 초대했고, 해결되지 않은 경우 현장에서 세팅을 지원했습니다.
- 운영 표준: 신청 단계에서 `노션 가입 이메일`과 `평소 이메일`을 분리해 받습니다. 첫 수업 24시간 전 자동 체크리스트로 열기·편집·댓글 세 가지를 자가 검증하게 합니다.

### 2. Claude Pro를 수업 전에 결제해야 하나요?

- 질문 맥락: 현장에서 결제하다가 실습 속도를 놓칠까 걱정했습니다.
- 당시 답변: 실습 비중이 높으므로 수업 전에 결제·로그인을 마치는 편이 좋다고 안내했습니다.
- 운영 표준: 필수/권장 플랜, 예상 비용, 무료 대안, 환불·해지 경로를 한 장짜리 사전 준비표로 제공합니다.

### 3. 입장 QR은 언제 활성화되고 어느 입구로 가야 하나요?

- 관찰: 첫날 세 명 이상이 QR 활성화, 지하 1층 대기 위치, 건물·입구를 질문했습니다.
- 당시 답변: QR이 정시에 활성화된다고 안내했고, 이후 운영진이 30분 일찍 생성되도록 공간 측과 협의했습니다.
- 운영 표준: 지도 링크만 보내지 말고 건물 외관, 입구, 엘리베이터, 세미나룸까지 4컷 경로를 전날과 당일 두 번 보냅니다.

### 4. 1주차 과제는 무엇을 어디에 써야 하나요?

- 질문 맥락: 과제를 들은 기억은 있지만 제출 위치와 범위가 불분명했습니다.
- 당시 답변: 4주 동안 풀 업무 문제를 정하고 간단히 작성하면 되며, 문제를 완벽히 정리하지 말고 친구에게 말하듯 현재 상황을 적으라고 안내했습니다.
- 학습 원칙: 정답을 먼저 요구하지 않습니다. `현재 문제 → 반복되는 상황 → 원하는 변화 → 제약` 네 칸으로 시작하고 수업에서 HMW와 PRD로 다듬습니다.

### 5. 한 번 쓸 작업도 AI Agent로 만들어야 하나요?

- 질문 맥락: 경력기술서를 바탕으로 포트폴리오를 빠르게 만들어야 했습니다.
- 당시 답변: 한 번만 할 일은 GPT나 Claude의 대화·Artifact 방식이 유리하고, 반복할 일은 Agent가 유리합니다. 구축비용을 고려해 대략 5회 이상 재사용할 때 Agent를 검토한다는 실무 기준이 제시됐습니다.
- 재사용 가능한 판단 카드:
  1. 1~2회면 대화형 도구로 시작합니다.
  2. 같은 입력·출력 구조가 5회 이상 반복되면 Agent 후보입니다.
  3. 실패 비용이 크거나 승인 절차가 필요하면 자동화 전에 검증 단계를 둡니다.

### 6. 일반 직무 포트폴리오는 어떤 도구와 레퍼런스를 쓰나요?

- 당시 답변: Claude에서도 Artifact 결과물을 대화로 수정할 수 있습니다. 시각 레퍼런스는 Pinterest에서 회사·직무·색상·스타일과 `Portfolio/Design/Company`를 조합해 검색하고, 국내 사례는 노트폴리오를 참고하라고 안내했습니다.
- 관심 신호: 단순 도구 사용보다 이직·경력 정리처럼 개인의 실제 결과물과 연결될 때 질문이 구체화됐습니다.

### 7. 가장 낮은 요금제로도 멀티 Agent를 돌릴 수 있나요?

- 당시 답변: 가능하지만 작업 난이도가 모델 역량을 넘으면 오래 멈춰 있을 수 있습니다. 그때는 작업을 중단하고 더 높은 모델로 바꾸거나 단계를 나눕니다.
- 운영 표준: 실습마다 `최저 권장 모델`, `예상 소요시간`, `중단 기준`, `대체 경로`를 함께 표시합니다.

### 8. 로컬 LLM과 클라우드 모델은 일을 어떻게 나누나요?

- 질문 맥락: 토큰 비용을 줄이려 했고, 필요한 하드웨어와 품질 저하를 걱정했습니다.
- 당시 답변: 계획·평가처럼 판단이 필요한 일은 고성능 클라우드 모델, 단순 실행은 가벼운 로컬 모델이나 하위 모델에 맡길 수 있다는 분업 원칙이 제시됐습니다. 로컬 모델은 낮은 사양에서도 가능하지만 고성능 모델은 큰 초기비용이 듭니다.
- 핵심 문장: `뇌 역할은 고성능 모델, 손 역할은 저비용·로컬 모델`.
- 주의: 당시 대화의 구체 모델명·메모리·가격은 시점 의존적이므로 구매 전 재검증이 필요합니다.

### 9. Agent가 15분 넘게 실행 중이면 기다려야 하나요?

- 당시 답변: 7분 이상 진전이 없으면 한 번 멈추고 이전 프롬프트를 재실행합니다. 반복 실패하면 컨텍스트가 가득 찼는지, 작업이 모델 난이도를 넘는지 확인합니다. 품질이 부족하면 먼저 effort를 올리고, 그래도 안 되면 모델을 올립니다.
- 설명 프레임: `모델 = 풀 수 있는 과제 난이도`, `effort = 생각에 쓰는 시간`.
- 운영 표준: 중단·재시도·모델 변경·컨텍스트 정리 순서가 있는 트러블슈팅 표를 제공합니다.

### 10. GitHub 자료나 Skill은 어떻게 설치하나요?

- 당시 답변: 파일을 첨부하고 “해당 스킬 설치해줘”라고 요청하거나, GitHub 링크를 복사해 Cowork에 실행해달라고 요청하는 방식이 공유됐습니다.
- 관심 신호: 긴 설명보다 바로 실행할 수 있는 한 줄 프롬프트와 예제가 참여 반응을 만들었습니다.

### 11. AI 결과물을 더 쉽게 이해하게 만들 수 있나요?

- 관찰: 과정 후반에 AI 출력이 어렵다는 문제와 함께 ASD-STE100, 출력 형식 선택 가이드가 공유됐습니다.
- 운영 표준: 결과를 생성하는 법만 가르치지 말고 `짧은 문장`, `한 문장 한 의미`, `필요한 출력 형식 선택`, `사실 검증`까지 품질 기준으로 포함합니다.

## 바로 재사용할 운영 답변 템플릿

> 먼저 이 일이 몇 번 반복되는지 확인해 주세요. 한두 번이면 대화형 AI로 빠르게 만들고, 같은 구조로 5회 이상 반복되면 Agent로 전환합니다. 계획·평가는 고성능 모델, 반복 실행은 저비용 모델로 나눕니다. 7분 이상 진전이 없으면 중단 → 재실행 → 컨텍스트 확인 → 모델 변경 순서로 점검합니다.

이 템플릿은 AWAC 1기에서 서로 떨어져 있던 질문들을 하나의 결정 흐름으로 묶은 것입니다.

## 강의 중 공통 운영

### 기본 시간 비율

- 강의·사례: 40분
- 공통 입력 실습: 35분
- 개인 적용 계획: 25분
- 피드백: 20분

개인 프로젝트를 수업 시간 안에 완성시키지 않습니다. 공통 사례로 판단 기준을 익힌 뒤 개인 적용은 과제로 이어가고, 수업에서는 다음 행동을 정하는 데 집중합니다.

### 트랙 선택

- **개인 집중:** 생각을 천천히 정리해야 하거나 직무가 독특한 참여자
- **직무 유사 페어:** 결과물 목적과 속도가 비슷한 두 참여자
- **확장:** 기본 산출물을 마친 뒤 멀티 Agent·라우팅·추가 검수를 다룰 참여자

팀은 인원 수를 맞추기 위해 만들지 않습니다. 직무명이 아니라 만들려는 결과, 현재 속도, 피드백 목적을 기준으로 매칭합니다.

### 4분 마이크로 클리닉

1. 30초: 하려는 결과
2. 60초: 현재 근거와 막힌 판단
3. 90초: 강사의 질문과 기준 제안
4. 40초: 참여자가 선택한 다음 행동
5. 20초: 기록 확인

모든 참여자가 주차마다 최소 한 번은 받도록 명단에 체크합니다. 답을 대신 만들기보다 다음 판단 하나를 명확하게 합니다.

### 질문을 받는 순서

1. 하려던 결과를 확인합니다.
2. 지금 보이는 사실과 참가자의 추론을 나눕니다.
3. 이미 해본 것을 확인합니다.
4. 가장 작은 다음 행동 하나를 제안합니다.
5. 해결 과정과 기준을 전체에게 익명 공유합니다.

### 실행이 멈췄을 때

- 7분 이상 화면 변화가 없으면 중단을 권합니다.
- 같은 프롬프트로 한 번 재실행합니다.
- 작업을 계획/수집/작성/검수로 나눕니다.
- 컨텍스트 포화 여부를 확인합니다.
- effort를 먼저 조정하고 모델은 그다음에 올립니다.
- 계속 실패하면 미완료 상태와 질문을 기록합니다.

### 참가자 속도가 다를 때

- 기본 트랙: 단일 Agent를 두 번 실행
- 확장 트랙: 역할 두 개로만 분리
- 고급 트랙: 계획·실행·평가와 모델 라우팅

빠른 참가자에게 Agent 수를 늘리게 하지 말고 검수·실패·재사용 근거를 강화하게 합니다.

느린 참가자에게 미완성 생각을 즉석에서 팀에 공유하도록 요구하지 않습니다. 사전 작성, 개인 집중, 비동기 피드백 중 하나로 전환합니다.

### 마지막 회차에 참여하지 못할 때

- 발표 자료, 6분 화면 녹화 또는 음성 설명 중 하나를 받습니다.
- 동료 결과물은 개인정보를 제거한 요약으로 열람하게 합니다.
- 72시간 안에 `통과 근거 / 보완 1개 / 다음 30일` 형식으로 피드백합니다.
- 건강·업무·시험 등 개인 사유는 공개 기록에 남기지 않습니다.

## 발표 피드백 문장

- “좋다”보다 “어떤 근거 때문에 통과인지”를 말합니다.
- “더 만들어보세요”보다 “어떤 조건에서 확장할지”를 묻습니다.
- “자동화가 됐네요”보다 “사람이 어디에서 승인하는지”를 확인합니다.
- “모델을 높이세요”보다 “과제 난이도와 effort 중 무엇이 부족한지”를 구분합니다.

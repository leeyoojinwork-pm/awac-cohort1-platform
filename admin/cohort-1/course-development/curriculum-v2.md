# AWAC V2 4주 커리큘럼

## 과정 목표

4주가 끝나면 참여자는 자신의 반복 업무 하나를 골라, Agent가 필요한지 판단하고, 단일 또는 멀티 Agent의 역할·입력·검수·중단 조건을 설계해 두 번 실행한 근거를 발표합니다.

## 수료 기준

- 문제정의가 기능 아이디어가 아니라 관찰된 업무 간극으로 적혀 있다.
- Agent를 만들지 않는 대안과 비교했다.
- 입력·처리·분기·출력·검수 흐름이 연결돼 있다.
- 모델과 비용 선택 이유, 사람 승인, 중단 조건이 있다.
- 서로 다른 입력으로 최소 두 번 실행하고 결과 차이를 기록했다.
- 결과물의 사실성·가독성·형식을 사람이 검수했다.

## 개인톡 피드백을 반영한 운영 구조

1기 개인톡 15개를 확인한 결과, 초보자 친화적 자료·실제 업무 적용·문제부터 실행까지의 구조가 만족 이유로 나타났습니다. 반면 한 참여자는 직무와 작성 속도가 다른 팀에서 개인 프로젝트를 즉석으로 완성하는 활동이 부담스럽다고 평가했습니다.

V2는 다음 순서를 고정합니다.

`강사 사례 → 공통 입력 실습 → 개인 적용 계획 → 4분 피드백 → 개인 과제`

참여자는 매주 한 가지 방식을 선택합니다.

- **개인 집중:** 혼자 정리한 뒤 강사 피드백을 받습니다.
- **직무 유사 페어:** 비슷한 결과물을 만드는 2명이 기준만 교환합니다.
- **확장 트랙:** 기본 산출물을 끝낸 뒤 멀티 Agent·라우팅·추가 검수를 다룹니다.

팀 공유는 목적·입력·완료 기준이 같을 때만 사용합니다. 속도가 다르거나 미완성 생각을 정리하는 단계에서는 강제하지 않습니다.

## 0. 수업 전 프리플라이트

### 참가자 완료 항목

1. 노션 페이지 열기
2. 개인 페이지에 한 줄 작성
3. 사용할 AI 서비스 로그인과 플랜 확인
4. 샘플 파일 업로드·다운로드 확인
5. 민감정보가 제거된 실습 자료 한 개 준비

### 운영진 완료 항목

- 편집권한을 실제 가입 이메일로 대조
- 입장 QR 활성화 시각과 4컷 동선 발송
- 무료/유료 대안과 예상 사용량 안내
- 도움 요청 형식 배포: `현재 화면 / 하려던 일 / 이미 해본 것 / 오류 문구`

## 1주차 — 도구보다 먼저 문제를 쓴다

### 핵심 질문

`지금 내가 해결하려는 것은 기능인가, 반복되는 업무 문제인가?`

### 학습목표

- 현재 상태와 원하는 상태의 차이를 말할 수 있다.
- 반복 빈도와 실패 비용을 근거로 적을 수 있다.
- HMW 질문과 성공 신호를 만든다.

- Agent를 쓰지 않는 대안 한 개 작성

## 2주차 — Agent를 만들지 않을 기준부터 세운다

### 핵심 질문

`대화형 AI로 끝낼 일인가, 재사용할 Agent를 만들 일인가?`

### 학습목표

- 1회성·반복성 작업을 구분한다.
- 역할·입력·절차·출력·검수로 Agent 명세를 쓴다.
- 작은 PoC의 통과 기준을 정한다.

### Build-or-not 기준

| 반복 | 기본 선택 | 예외 |
|---:|---|---|
| 1회 | 대화형 AI·Artifact | 실패비용이 매우 크면 검수 흐름부터 설계 |
| 2~4회 | 프롬프트·템플릿 재사용 | 입력 구조가 안정적이면 작은 PoC |
| 5회 이상 | Agent 후보 | 매번 판단이 크게 달라지면 사람 중심 유지 |

### 120분 진행

| 시간 | 내용 | 산출물 |
|---:|---|---|
| 0~20분 | 강사 사례: Agent를 만들지 않은 결정 | 반복·비용 근거 |
| 20~40분 | 공통 사례 Build-or-not | 선택과 이유 |
| 40~60분 | 공통 Agent 명세 6칸 | 샘플 agent-spec |
| 60~80분 | 같은 입력으로 첫 실행·통과 기준 비교 | 공통 run-01 |
| 80~100분 | 개인 업무로 전환 계획 | agent-spec.md |
| 100~115분 | 4분 마이크로 클리닉 순환 | 수정 기준 1개 |
| 115~120분 | 과제·Exit ticket | 개인 실행 계획 |

### 과제

- 개인 업무 입력으로 첫 번째 실행
- 같은 구조의 다른 입력으로 두 번째 실행
- 두 실행의 차이, 수정한 기준, 사람 승인 지점 기록

## 3주차 — 멀티 Agent를 비용과 복구까지 운영한다

### 핵심 질문

`역할을 나누면 정말 더 좋아지는가, 아니면 비용만 늘어나는가?`

### 학습목표

- 멀티 Agent가 필요한 조건을 설명한다.
- 계획·실행·평가를 다른 모델에 라우팅한다.
- 실행 정지·컨텍스트 포화·품질 부족을 구분해 복구한다.

### 4층 구조

1. **설정:** 역할, 권한, 사용할 자료
2. **실행:** 작업 순서, 전달 형식, 분기
3. **출력:** 최종 산출물과 중간 산출물
4. **로그:** 실패, 수정 이유, 다음 기준

### 7분 복구 규칙

`중단 → 같은 프롬프트 재실행 → 작업 분할 → 컨텍스트 정리 → effort 조정 → 모델 변경 → 사람에게 질문`

### 120분 진행

| 시간 | 내용 | 산출물 |
|---:|---|---|
| 0~20분 | 강사 사례: 단일 Agent의 실패와 확장 판단 | 유지/확장 결정 |
| 20~40분 | 역할 분리·모델 라우팅 | 역할 카드 |
| 40~60분 | 공통 실패 시나리오 7분 복구 | recovery-log.md |
| 60~80분 | 공통 멀티 Agent 4층 구조 | 샘플 flow.md |
| 80~100분 | 개인 routing-map 작성 | routing-map.md |
| 100~115분 | 4분 마이크로 클리닉 순환 | 축소/유지/확장 |
| 115~120분 | 과제·Exit ticket | 개인 복구 실험 |

## 4주차 — 생성보다 검수와 설명을 완성한다

### 핵심 질문

`이 결과를 사람이 믿고 다음 행동에 쓸 수 있는가?`

### 학습목표

- 사실·추론·미확인을 분리한다.
- 읽기 쉬운 문장과 적합한 출력 형식을 선택한다.
- 시연에서 문제, 판단, 실행, 검수, 근거를 설명한다.
- 기업·면접관이 이해할 수 있는 포트폴리오 스토리로 바꾼다.

### 품질 게이트

1. **사실성:** 출처가 필요한 주장에 근거가 있는가?
2. **판단 일치:** 처음 정한 성공 기준을 만족하는가?
3. **가독성:** 한 문장 한 의미, 짧은 문장, 용어 일관성인가?
4. **형식 적합:** 글·표·도식·웹·영상 중 사용 상황에 맞는가?
5. **사람 승인:** 외부 발송·결제·평가 전에 승인했는가?

### 기업이 보는 좋은 AI 활용

1. 해결하려는 업무 문제가 구체적이다.
2. AI를 선택한 이유와 선택하지 않은 대안이 있다.
3. 입력·출력·사람 승인·실패 대응이 설명된다.
4. 서로 다른 입력으로 두 번 실행한 근거가 있다.
5. 한계와 다음 검증을 숨기지 않는다.

| 0~20분 | 강사 사례: 작동하는 데모를 포트폴리오로 바꾸기 | 평가 기준 |
| 20~40분 | 공통 결과물 품질 게이트 | PASS/REVIEW/HOLD |
| 40~60분 | 개인 결과물 검수·수정 | final-review.md |

| 105~120분 | 결석자용 비동기 패키지·30일 계획 | 공유 링크·재사용 조건 |

## 평가 루브릭

| 항목 | 0 | 1 | 2 |
|---|---|---|---|
| 문제 근거 | 아이디어만 있음 | 경험 설명 | 빈도·시간·오류 근거 |
| Agent 적합성 | 비교 없음 | 대안 언급 | Build-or-not 근거 명확 |
